## vibe-project-init — Vibe 项目初始化 Skill

> 「Vibe coder toolkit」第二个核心工具，帮你从第一天就给 AI 项目立好规矩，从源头防烂尾。

---

## 安装

将本目录放到 `~/.workbuddy/skills/vibe-project-init/`，WorkBuddy 自动加载。

---

## 用法

### 触发词

| 你说                                      | 系统执行                              |
| --------------------------------------- | --------------------------------- |
| "初始化项目" / "搭治理骨架"                       | 全流程交互：7轮问答+补充信息采集，自动生成治理骨架        |
| "init project" / "新项目" / "vibe project" | 同上，英文触发词适配                        |
| "/vibe-project-init resume"             | 恢复中断的初始化流程，无需重填已答内容               |
| "帮我用这套治理体系管现有项目"                        | 进入适配模式：只读扫描存量项目、生成草稿、等你选方案后写入治理骨架 |

也可通过 `/vibe-project-init` 斜杠命令触发。

### 命令行

bash

全量初始化（默认）
bash scripts/vibe-project-init.sh start

恢复中断的初始化
bash scripts/vibe-project-init.sh resume

查看帮助
bash scripts/vibe-project-init.sh -h

纯文本
**无需传项目路径**——脚本自动检测当前 WorkBuddy 关联的项目目录，在任意子目录运行均可。

## 适配模式（管你已有的项目）

你已经有代码、但还没用我们的治理体系？用适配模式，不用把项目推倒重来。

> 触发：对我说「帮我用这套治理体系管现有项目」。它和上面的「新建模式」是两套独立流程，不会混在一起，也绝不自动触发、绝不用于新建项目。

它会做这几件事（全程你说了算）：

1. **先看看能不能接**：检查项目是不是 git 仓库、有没有已经接过治理。不符合条件会直接告诉你，不会偷偷改你的东西。
2. **只读扫描**：看清你有哪些模块（比如有 `pc/` 目录就是 PC 端、有 `android/` 就是安卓端）、历史待办清单写在哪、还缺哪些治理规矩（比如 commit 有没有前缀、有没有跨端日志）。
3. **出草稿**：把扫描结果写成几份草稿，放在 `.workbuddy/memory/drafts/` 这个临时目录里，**绝不动你的正式文件，也不改你原来的待办清单**。
4. **等你拍板**：给你三个选项——全量接入 / 只接指定模块 / 先看草稿内容。你没选，它就不动。
5. **太复杂就喊停**：模块超过 3 个、技术栈超过 3 种、或者历史提交毫无规律，它会建议你升级到 Coordinator 数字分身兜底，不硬来。

接入完成后，会顺手把这次改动登记到 `SKILL_REGISTRY.md`（版本升到 v1.1.0）。

## 核心逻辑（初始化步骤）

| 步骤          | 系统执行                                           | 通过条件                 |
| ----------- | ---------------------------------------------- | -------------------- |
| 1. 采集项目基本信息 | 询问项目名称、用途，自动记录                                 | 项目名称非空               |
| 2. 识别使用场景   | 提供「电脑浏览器/手机App/后台自动跑」等选项，自动映射为模块               | 至少选中1个场景             |
| 3. 模块命名适配   | 支持用户自定义模块名（如「PC端/安卓端/云端」或「前端/后端/数据库」），动态生成对应文件 | 模块名非空、无重复            |
| 4. 确认角色分工   | 询问「单AI负责/多AI分责/人参与」模式，自动生成角色护栏                 | 分工模式明确               |
| 5. 采集技术栈    | 记录用户提到的工具/平台，自动写入项目画像                          | 可选，无则留空              |
| 6. 识别历史痛点   | 提供「AI撒谎/越界/忘约定/多窗口混乱」等选项，自动生成对应铁律              | 可选，无则默认基础铁律          |
| 7. Git 存档引导 | 询问是否开「后悔药」，自动后台建立存档机制（无需用户操作）                  | 选「不开」则提示功能受限，不影响其他功能 |
| 8. 补充信息采集   | 支持用户输入自然语言补充需求，自动存入项目档案                        | 可选，直接回车跳过            |

## 常见问题

### Q: 我完全不懂代码/Git，能用吗？

能。全程在 WorkBuddy 聊天框交互，无需碰终端、无需懂任何技术概念。Git 存档由工具自动建立，你只需要知道「改崩了能回退」就行。

### Q: 会改我现有的业务代码吗？

不会。本工具只生成管理类文件（`memory/`目录、`TASKS-*.md`等），绝不碰你的业务代码，原有项目内容原封不动。

### Q: 初始化错了能改吗？

能。直接重新运行 `初始化项目`命令，已填内容会自动保留，只需修改错误项即可。

### Q: 和 commit-check 怎么配合？

`vibe-project-init`是地基，帮你立好规矩；`commit-check`是验收工具，验证 AI 提交是否合规。初始化完成后，每次 AI 改完代码跑一次 `commit-check`，就能防撒谎、防越界。

### Q: 生成的文件我能改吗？

可以，但建议只让 coordinator（你）修改 `memory/`下的核心文件，AI 仅能读、不能改。工具会自动校验修改权限，防止越界。

### Q: 没有 Git 能用吗？

能。只是 `commit-check`的「提交真实性验证」功能会受限，其他治理功能（任务管理、铁律约束、契约对齐）完全正常。

### Q: 能管我已有的项目吗？

能，用**适配模式**。对我说「帮我用这套治理体系管现有项目」，它会只读扫描你现有的代码和待办，先出草稿给你看，等你选了接入方案才写入治理骨架——不会动你的业务代码，也不会改你原来的待办文件。适配复杂度过高时会建议你升级到 Coordinator 数字分身兜底，不硬来。
