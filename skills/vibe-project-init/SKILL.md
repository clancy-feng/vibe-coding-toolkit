# Project Init — AI 项目治理骨架初始化

## 定位

用户（非开发背景、用 AI 做项目的人）刚有个想法或已有项目但很乱。
本 Skill 通过**交互式问答 + 自然语言解析**两种方式，帮用户把模糊想法翻译成治理骨架。

> ⚠️ 本 Skill 不直接改业务代码。它只生成治理文件（memory/、TASKS-*、project.config）。
> 业务代码由后续 PACE 循环（task-manager + commit-check）管。

## 前置

- 确保你的聊天窗口已打开项目文件夹（WorkBuddy 已关联当前目录）
- 若项目已有 `memory/` 或 `TASKS-*` 或 `project.config`，先询问用户是否覆盖

## 交互模式（默认）

按以下 7 轮问答，每轮都允许用户用"自然语言一段话"代替选择题。
若用户一段话描述了项目，跳过问答，直接进入解析 + 确认。

### 第 1 轮：项目是什么

问：项目是干什么的？（例：抢购工具、库存管理、博客）
存：`project_name`、`project_desc`

### 第 2 轮：使用场景（替代"几端"）

问：用户在哪里用这个东西？（多选，生活化语言）
选项：

1. 电脑浏览器（像淘宝网页）
2. 手机装 App（像微信）
3. 手机浏览器（像移动网页）
4. 后台自动跑（像定时任务）
5. 其他（用户说）
   存：`usage_places[]` → 翻译成模块候选名

### 第 3 轮：模块命名

把上一轮的选项翻译成模块名候选，让用户确认/自起：
例：电脑浏览器 → "PC端"或"前台"；后台 → "云端"或"服务器"
存：`modules[]`（最终模块名列表）

### 第 4 轮：角色分工

问：谁负责各模块？

1. 同一个 AI 负责所有
2. 不同 AI 各管一块
3. 人手动参与一部分
   存：`team_mode`

### 第 5 轮：技术栈（生活化）

问：用到哪些工具/平台？（多选 + "你帮我看看"选项）
存：`tech_stack[]`

### 第 6 轮：痛点（为铁律定制）

问：之前开发遇到过哪些坑？（多选）

1. AI 说改了但没改
2. AI 改了不该改的（越界）
3. AI 忘约定
4. 多窗口不知道对方在干啥
5. 项目越做越乱
6. 其他
   存：`pain_points[]`

### 第 7 轮：Git 引导（⭐ 必须）

问：GIT项目代码文档版本管理（存档/回退）的情况？

1. 已经有了
2. 还没弄，帮我开一个
3. 不需要

> 若选 1：检测现有存档状态。
> 若选 2：本 Skill 执行 `git init`，生成 `.gitignore`，做首次 commit。
> 若选 3：提示：commit-check 的"真实性验证"和 task-manager review 的 `git show` 会受限，但其余功能正常。

## 自然语言模式（备选）

用户若直接说一段话（例："我做了个跨三端抢购，PC端Node.js安卓端Kotlin云端腾讯云，三个AI各管各的，常遇到AI越界和虚假提交"），则：

1. 解析出：`project_name`、`modules[]`、`tech_stack[]`、`team_mode`、`pain_points[]`
2. 回显给用户确认："我理解你的项目是这样：… 对吗？"
3. 确认后进入生成。

## 适配模式（存量项目接入治理）

> 触发词：「帮我用这套治理体系管现有项目」
> 与「新建模式」（从零生成空骨架）完全独立、并列。仅用于**已有代码但无治理文件**的存量项目。绝不自动触发，绝不用于新建项目。

### 步骤 1：前置只读校验（绝不碰任何文件）

- 检查当前项目根目录是否已是 git 仓库；不是 → 直接报错「该项目未初始化 git 仓库，请先运行 git init 后再适配」，不自动建仓库。
- 检查 `.workbuddy/memory/` 下是否已存在正式治理文件（`MEMORY.md` / `RULES.md` / `ROLES.md` / `CONTRACT.md` / `ARCHIVE.md`）；已存在 → 报错「该项目已接入治理体系，无需重复适配」。

### 步骤 2：只读扫描（只扫不写）

识别 3 类信息，全部记在内存，不生成任何文件：

1. **模块**：有 `pc/` → PC 模块；有 `android/` → 安卓模块；有 `cloud/` → 云端模块；有 `package.json` → Node.js 项目。用自然语言描述。
2. **历史 TODO**：找 `TODO.md` / `todo.txt` / `issues` 等任务文件，统计待办条数，按模块分类。
3. **合规缺口**：对比通用治理规则，列出缺什么（有无 commit 前缀、有无跨端日志、有无 Skill 版本记录），用听得懂的话讲。

### 步骤 3：生成草稿（只放临时目录）

生成 3 份草稿，**全部放在 `.workbuddy/memory/drafts/`**，绝不碰正式治理目录：

1. `RULES.draft.md`：通用铁律 + 模块专属规则（如 PC 模块前缀 `[PC]`、安卓 `[ANDROID]`）。
2. `TASKS-<模块>.draft.md`：把历史 TODO 按模块拆成正式任务，每条标 `[历史迁移]`，**不改动原 TODO 文件**。
3. `ADAPT_REPORT.draft.md`：合规缺口清单 + 适配建议。

生成后告知：「适配草稿已生成，放在 `.workbuddy/memory/drafts/` 目录下，你要不要先看草稿内容，还是直接选适配方案？」

### 步骤 4：等你的选择（绝不自作主张）

给 3 个选项，你选了才动：

1. **全量适配**：把草稿写入正式治理目录，迁移所有历史任务。
2. **仅适配指定模块**：只写你指定的模块的治理文件，其他忽略。
3. **先看草稿内容**：把草稿核心规则用自然语言念给你听，你确认后再问选哪个。

- 选 ① / ②：才把 drafts 文件挪到正式 `.workbuddy/memory/`，写完按 health-check 分级规则做首次体检（health-check 待上线时降级为提示，不卡死）。
- 选 ③：念完再问，不催、不自动写入。

### 步骤 5：复杂度熔断（必须执行）

扫描到以下任一情况，直接报「该项目适配复杂度过高（原因：XXX），建议申请 Coordinator 数字分身兜底处理」，不强行适配：

- 模块超过 3 个（如同时有 PC / 安卓 / 云端 / 硬件 / IoT）；
- 混合 3 种以上技术栈（如 Node.js / Java / Python / Go）；
- 历史 commit 完全无规律，找不到任何前缀或归属标记。

### 关联规则

- 迁移的历史任务必须新开正式任务 ID、标 `[历史迁移]`，**绝不修改原 TODO / CHANGELOG 等现有文件**（符合「已归档内容不可修改」铁律）。
- 适配完成后更新用户级 `SKILL_REGISTRY.md`，版本记 **v1.1.0**，变更：「新增存量项目适配模式，支持历史TODO迁移、合规缺口扫描」。
- 不添加规格未说的功能（如自动改业务代码、自动补 commit 前缀），所有写入动作必须等你明确授权。

## 生成产物
本 Skill 将在项目根目录下自动生成以下治理文件（无需手动创建）：

1. **系统记忆中心（memory/）**
   - `MEMORY.md`：全局地图，包含快速查阅表。
   - `PROJECT_PROFILE.md`：项目画像。
   - **`RULES.md`：行为规范（核心铁律已预置，无需用户编写）**。
   - `ROLES.md`：角色分工与护栏。
   - `CONTRACT.md`：契约文件。
   - `ARCHIVE.md`：历史档案。

2. **任务看板（TASKS-*.md）**
   为每个模块生成独立的任务文件（如 `TASKS-PC.md`），用于追踪进度。

3. **配置文件**
   `memory/project.config`：项目核心配置，供其他 Skill 读取。

- “创建一个新任务：XXX”（调用 `task-manager`）

## 关联 Skill

- 下游：`task-manager`（读 TASKS-*.md + project.config）
- 下游：`commit-check`（验证每次提交）
- 上游：无（本 Skill 是起点）

## 铁律对齐

- 本 Skill 自动注入预置的**基础铁律模板**，确保项目合规性。
- 本 Skill 生成的 ROLES.md 中 DONT_TOUCH 规则，必须与后续 commit-check 的越界检查一致
- 本 Skill 生成的 RULES.md 中 Git 纪律（前缀 `[PC]/[ANDROID]/[CLOUD]/[MEMORY]/[DOCS]/[FIX]/[TOOL]`），必须与 commit-check 一致
- 本 Skill 生成的 CONTRACT.md 中"只有 coordinator 可改"的护栏，必须与 task-manager 的写权限一致
- **交互友好声明：**
  - 本 Skill 在运行过程中如需获取用户名/邮箱以便存档，将直接在当前聊天窗口提问，不会弹出终端或后台静默失败。
