# task-manager 使用手册（用户版）

你只用做四件事：**说清楚、看返回、拍板、两个接点上手操作**。文件读写和命令执行都归 AI。

## 一、三点注意

- 磁盘文件是唯一真相，AI 的回复只是通知，不是事实。
- 所有请求先给 Coordinator。
- 你只在两个接点（第四节）亲手操作，其余交给 AI。

## 二、三个角色

| 角色                         | 你跟它说什么                      |
| -------------------------- | --------------------------- |
| 你（owner）                   | 提需求、看返回、拍板 / 驳回             |
| Coordinator（AI 窗口）         | 所有请求先给它；它分析、建任务、调度、更新任务     |
| 执行团队（PC / 安卓 / 云端等各 AI 窗口） | 不直连；只认 Coordinator 建好的任务去干活 |

## 三、工作循环

1. 提需求给 Coordinator：说清现象 + 上下文（日志路径、复现步骤）。
2. Coordinator 建任务到 `TASKS-*.md`，回你"已建 XXX（含task_id），等待认领"。
3. 看返回：
   - 满意 → 切到执行窗口，说"处理 `<task_id>`"（接第四节①）。
   - 有补充 → 把细节回给 Coordinator，它二次分析（原地 `update` 或建新任务）。
4. 执行窗口认领 → 修复 → `complete`；你按第四节②验收。

## 四、两个必须你亲手做的接点

### 接点① 派单

切到对应执行窗口（PC / 安卓 / 云端），说一句：

> 处理 `<task_id>`

窗口会自己读 `task-manager` skill + `WORKFLOW_TASK_DRIVEN.md` + `TASKS-*.md`，执行全套：认领、改代码、按模块前缀提交、`complete` 回填三段、自跑 commit-check。

### 接点② 验收

1. 收执行窗口回复（含核验指引：指向文件、校验法如 `git log <id>`）。
2. 自己打开 `TASKS-*.md` 核验：状态真 ✅、三段齐、commit 真实存在。
3. 对 Coordinator 说结论："已核验 XXX 状态✅、commit 真实存在，请核验"，也可以直接把任务窗口的输出贴过来。
4. 自己去生产 / 预发环境实测。
5. 实测 OK → 收工；不行 → 把现象回 Coordinator（它建衍生任务或打回），你再带到执行窗口。

只说"PC 说修完了"、没提文件核验 → Coordinator 驳回，要结论。

## 五、你不要做

- 手动编辑 `TASKS-*.md`。
- 直接命令执行团队"去干 XXX"。
- 对Coordinator一次说多个任务。

## 六、完整例子

**你**：PC 端登录接口生产环境超时，日志 `rush-runlog-20260716.txt` 第 3 行 TIMEDOUT。先分析根因。

**Coordinator**：已建任务 `2026-07-15-PC-001`（📋 待处理）。

**你**：方案有局限。日志显示连接池耗尽，不是单纯超时。压测 concurrency=200 才出现。

**Coordinator**：`update` 问题描述为"连接池耗尽导致高并发登录超时（concurrency≥200 触发）"。

**你**：切到 PC 窗口，说"处理 `2026-07-15-PC-001`"。

**PC 窗口**：认领 → 修复 → `complete`（✅，脚本自跑 commit-check）。回复："已置 ✅，commit `<id>`，请核验：① 打开文件确认 ✅；② `git log <id>` 确认 commit 存在。"

**你**：打开 `TASKS-PC.md` 确认 ✅ 三段齐；`git log <id>` 确认 commit 存在。

**你**：对 Coordinator 说"已核验 `2026-07-15-PC-001` 状态✅、commit `<id>` 真实存在，确认完成"。

**Coordinator**：`review`，二次校验磁盘 + 跑 commit-check，回"验收通过"。

**你**：去预发环境压测 concurrency≥200 —— 不再超时 → 收工。

全程你没碰文件、没敲命令，只做了"说清楚 + 看返回 + 拍板 + 两个接点操作"。

## 七、速查表

| 你想做        | 你该说                                | 背后发生                            |
| ---------- | ---------------------------------- | ------------------------------- |
| 报 bug / 需求 | "PC 端…超时，日志在…"                     | Coordinator `create` 任务（📋）     |
| 方案不对、补充    | "方案有局限，补充…"                        | 未认领→`update`；已认领→`create` 关联新任务 |
| 让团队动手（接点①） | 切到执行窗口说"处理 XXX"                    | 窗口读文档后 `claim`→修复→`complete`（✅） |
| 验收（接点②）    | 核验文件后说"已核验 XXX ✅、commit 真实存在，确认完成" | Coordinator 二次校验磁盘 → 你实测 → 反馈闭环 |
| 驳回 / 打回    | "测了不行，因为…"                         | 回退 / 建衍生任务 / 重做                 |
