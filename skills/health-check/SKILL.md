# health-check 项目体检 Skill

> 脚本: `scripts/check.sh`（与 SKILL.md 同目录）
> 在项目根目录（含 `.git`）下运行，脚本自动检测仓库路径与 `.workbuddy/memory/`。
> 是 Vibe 治理框架第四核心组件，与 `vibe-project-init` / `commit-check` / `task-manager` 并列。

## 核心定位（不可动摇）

**你是项目体检医生，不是修理工。**

1. **绝对禁止自动修改任何文件**（`TASKS-*.md` / `CONTRACT.md` / `CROSS_IMPACT_LOG.md` / `SKILL_REGISTRY.md` 等）。本 Skill 唯一会写入的文件是自己的审计日志 `.workbuddy/memory/HEALTH_AUDIT.md`。
2. **唯一职责**：扫描隐患 → 用非技术语言报告 → 提供选项 → 等待人类授权。
3. **所有修复动作必须通过调用 `task-manager` 新开任务执行**，绝不允许直接改磁盘业务/治理文件。

> **重建边界**：本 Skill 仅检测治理骨架丢失（P0）。若需重建骨架，请调用 `vibe-project-init` 的重建模式（Rebuild Mode），本 Skill 不负责生成治理文件。

## 触发条件（仅限以下三种）

| #   | 触发方式     | 说明                                                                         |
| --- | -------- | -------------------------------------------------------------------------- |
| 1   | **主动体检** | 人类说"给项目做个体检 / 项目体检 / 健康巡检 / 巡检一下" → 立即运行 `check.sh`                        |
| 2   | **后置巡检** | task-manager 将任务标记为 `✅ 已完成` 后自动触发。**MVP 不接自动触发（留 TODO）**，本期不改 task-manager |
| 3   | **定时巡检** | 人类明确授权开启后，每日固定时间触发。**默认关闭**                                                |

## MVP 巡检项（仅做这 3 项，不加戏）

### 巡检项 1 — 任务状态一致性（防假成功）

- 扫描所有 `TASKS-*.md` 中标记 `✅ 已完成` 的任务，提取同任务块内的 `**commit**: <id>`。
- 对每个 commit_id 执行 `git log <commit_id>`；若该 commit 不存在 → 判定 **P1**（假成功）。

### 巡检项 2 — 契约完整性（两步）

- **第一步（存在性）**：检查 `CONTRACT.md` 或 `CROSS_IMPACT_LOG.md` 是否存在；任一关键契约文件缺失 → 判定 **P0**（框架失效）。
- **第二步（超时）**：扫描 `CROSS_IMPACT_LOG.md` 的 `## 待裁决 (Pending)` 段下所有 `### [日期] …` 条目，取日期计算，超过 24 小时未更新 → 判定 **P1**。

### 巡检项 3 — Skill 版本一致性

- 读取 `SKILL_REGISTRY.md` 中每个 Skill 的当前版本号。
- 对比 `~/.workbuddy/skills/<name>/SKILL.md` 中的 `version` 字段（去 `v`、去引号后比较）。
- 不一致 → 判定 **P2**（规范偏差）；**SKILL.md 无 version 字段视为不一致 → P2**。

### 巡检项 4 — 跨模块改文件（P1，AI 行为合规，无 AI 裁量）

- 扫描最近 50 条 commit，提取**提交者（映射 AI 角色）**与**修改的文件路径前缀**：
  - `ai-pc` → `pc/`；`ai-android` → `android/`；`ai-cloud` → `cloud/`；非 AI 提交直接跳过。
- 若 AI 角色的归属模块与修改文件前缀不匹配，且 `CROSS_IMPACT_LOG.md` 的 `## 待裁决 (Pending)` 段下**无对应日期登记项** → 判定 **P1**（越权改非所属模块文件）。
- 规则焊死，AI 只读；非 AI 提交（人类/其他账号）不检。

### 巡检项 5 — 审计日志大小（P2，整洁类，纯规则）

- 检查 `.workbuddy/memory/HEALTH_AUDIT.md` 字节大小，超过 10MB（10485760 字节）→ 判定 **P2**（建议归档）。

### 巡检项 6 — TASKS 格式合规性（P2，纯规则）

- 扫所有 `TASKS-*.md`，每处 `**状态**: <取值>` 必须以合法状态 token 开头：
  `📋 待处理` / `🔄 处理中` / `✅ 已完成` / `⏸ 暂挂` / `✅ coordinator确认`。
- 允许末尾附加说明（commit hash、日期、审查备注）；不在集合内 → 判定 **P2**。
- 对齐本仓库真实格式（任务块为 `## [ID]` + `**状态**:`，非 `|` 表格式）；汇总表表头无 `**状态**:`，不误伤。
- `✅ coordinator确认` 为本仓库保留的 git 检查结果显示态（经用户 2026-07-20 裁定保留）。

### P1 自动升 P0 规则（焊死，无新增扫描）

- 连续 **3 次**体检发现 P0/P1 未清除（`STATE_FILE` 连续计数 ≥3），且本次存在 P1 → **本次所有 P1 直接升级为 P0** 输出，并提示"已自动升级为 P0 致命问题"。
- 仅重分类严重度，**不阻断 task-manager 流转**（冻结留 TODO，见联动 3）。

## 分级响应机制（严格执行，无 AI 裁量权）

对人类说的话必须严格照下表，等级判定完全由脚本给出，AI 不得自行升降级：

| 等级         | 定义                                            | 对人类说的话                                                                                                          |
| ---------- | --------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| **P0 致命级** | 框架失效（如 CONTRACT.md 丢失、git 仓库损坏、连续 3 次 P1 未处理） | "发现致命问题（P0）：[描述]。任务流转已锁定（声明式）。必须立即新开紧急修复任务（通常需调用 vibe-project-init 重建骨架）。唯一选项：1. 同意新开紧急修复任务（无「暂不处理」选项，拒绝即触发兜底）" |
| **P1 一般级** | 合规隐患（如假成功、Pending 超时）                         | "发现合规问题（P1）：[描述]。请选择处置方式：1. 立即新开修复任务　2. 稍后修复（24小时内必须处理，届时将再次告警）"                                                |
| **P2 轻微级** | 规范偏差（如 Skill 版本不一致）                           | "发现轻微偏差：[描述]。给你两个选项：1. 新开任务对齐　2. 忽略（默认）"                                                                        |

> P0 的"任务流转已锁定（声明式）"说明：见下文联动 3，冻结功能仅计数、留 TODO，暂不真正阻断任务流转。

## 联动逻辑（必须调用现有 Skill / 写审计）

1. **联动 task-manager**：人类选"1"（新开任务修复/对齐）时，调用 task-manager 的创建能力建修复任务：
   
   ```
   bash ~/.workbuddy/skills/task-manager/scripts/task-manager.sh create <module> "<title>" coordinator "<problem，必须包含 Ref: HEALTH-CHECK-[DATE]>"
   ```
   
   `<module>` 按隐患归属选择（任务假成功→对应 TASKS 文件的模块；契约→CONTRACT 归属方；版本→Skill）。描述中**必须包含** `Ref: HEALTH-CHECK-[DATE]` 以便追溯。

2. **联动审计日志**：所有巡检记录、人类选择、后续修复任务 ID，必须追加写入 `.workbuddy/memory/HEALTH_AUDIT.md`（由 `check.sh` 自动完成扫描记录部分；人类选择与修复任务 ID 由调用方在拍板后补记）。

3. **【当前状态】联动冻结机制（声明式，严禁实际阻断）**：
   
   - **严禁调用 `task-manager` 的任何冻结命令**（如 `handle_freeze`——该命令**目前不存在**）；**严禁脑补 `handle_freeze` 或自行实现冻结**。
   - 本 Skill 的"冻结"**仅为声明式**：连续 3 次 P0/P1 问题未获授权时，**仅在 `HEALTH_AUDIT.md` 记录"连续未授权计数"**；**真正的流转阻断（handle_freeze）留 TODO，本期不实现**。
   - 责任边界：health-check 只诊断、只记审计、只停**自身响应**；任何对 task-manager 任务流转的实际拦截，须由 task-manager 扩展后另行实现，不在本 Skill 范围内。

## 架构边界（铁律，不可动摇）

- **`check.sh` 是纯工具（pure tool）**：只做两件事——① 全量/单项巡检（无状态一次性扫描）；② `--respond <P0|P1|P2> "<选择>"` 对**单次**选择做无状态判定并输出话术。**脚本不追踪轮次、不维护对话状态**。
- **多轮对话拦截（警告 → 二次警告 → 兜底）是 Coordinator AI 的职责**，必须在 AI 对话层实现；**不得试图在 Shell 脚本里实现对话管理**（脚本无法多轮追踪人类输入，强塞只会产生不可控行为）。
- **AI 与脚本的分工**：脚本给出等级与单次判定；AI 负责把脚本输出转述给用户、识别连续违规、执行兜底（记审计 + 停响应）。本 Skill 不越界替 AI 做多轮决策。

## 错误判断拦截规则（AI 必须严格执行，不得遗漏）

> **总原则**：所有分级标准均为**人类预先定义的死值**，AI 仅读取等级、按规则输出对应选项，**绝对禁止自行推理、升降级**。AI 是「规则守门员」不是「决策者」：识别用户的违规选择并拦截，是强制职责。所有提示语必须用大白话，不出现「commit」「巡检注册表」等术语。

**各级别的合法/违规选择：**

| 级别     | 用户合法动作                                    | 判定为「错误判断」的违规选择（AI 必须拦截）                                                                                      |
| ------ | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| **P0** | 唯一合法：`1. 同意新开紧急修复任务`                      | ① 说"暂不处理/忽略/晚点再说"；② 说"同意"但未指向 `vibe-project-init` 重建（→追问"是否调用 vibe-project-init 重建骨架？"）；③ 选非"1"的数字           |
| **P1** | 二选一：`1. 立即新开修复任务` / `2. 稍后修复（24h 内必须处理）`  | ① 说"忽略/不用管/算了"；② 选"稍后修复"但未明确时间（→追问"请在 24 小时内处理，是否确认？"）；③ 选非"1/2"的数字                                          |
| **P2** | 二选一：`1. 新开优化任务` / `2. 忽略（默认，沉默 10 秒自动选②）` | ① 选"①"但未说明优化需求（→追问"请明确需要优化的具体内容？"）；② 提出超范围需求如改业务逻辑（→回复"该需求不属于 P2 优化范畴，请通过 task-manager 新建业务任务"）；③ 选非"1/2"的数字 |

**拦截三步流程：**

1. **首次识别到错误判断**：AI 立即复述该级别强制规则，用大白话告知违规后果。例（P0）：
   
   > ❌ 你的选择不符合 P0 级问题处理规则：治理骨架坏了，必须马上修，不然项目就废了。请重新选择：1. 同意新开紧急修复任务

2. **二次识别到错误判断**：AI 再次复述规则，明确告知将触发兜底。例（P0）：
   
   > ❌ 再次提醒：P0 问题不得延迟处理。若你仍拒绝同意重建，我将触发 Coordinator 数字分身兜底流程，暂停所有 AI 任务流转。请确认：1. 同意新开紧急修复任务　2. 触发兜底

3. **用户仍拒不改正**：AI 立即执行 ① 在 `HEALTH_AUDIT.md` 记录"用户连续 2 次做出 P0 级错误判断"；② 触发兜底（见下章）；③ 输出"已触发兜底流程，请联系 Coordinator 数字分身处理"，停止所有后续响应。

## 兜底触发条件（AI 自动执行，无需用户授权）

出现以下任一情况，AI 直接触发兜底，**不得询问用户意见**：

1. 连续 2 次做出同级别错误判断（如两次 P0 选"暂不处理"、两次 P1 选"忽略"）。
2. P0 问题用户拒绝处理后，24 小时内未主动发起重建。
3. P1 问题用户选"稍后修复"后，超过 24 小时仍未处理（下次巡检直接升 P0）。
4. 巡检中发现治理文件被恶意篡改（如 `CONTRACT.md` 被清空且用户无法说明原因）。

> **【实现说明 — 与联动 3 一致】** 本期 task-manager 尚无 `handle_freeze`，兜底中的"暂停/冻结所有任务流转"当前为**声明式（仅记审计 + 停响应）**：AI 在 `HEALTH_AUDIT.md` 记录兜底触发、连续错误判断计数与"已触发兜底流程"，并停止后续响应；**严禁调用 task-manager 任何冻结命令、严禁脑补 `handle_freeze`**；真正的流转阻断（`handle_freeze`）**留 TODO**，待 task-manager 扩展后启用。

> **审计留痕格式**（错误判断/拦截/兜底一律照此写入 `HEALTH_AUDIT.md`）：
> `[时间] 错误判断拦截：级别=P0，用户选择=暂不处理，处理结果=二次警告后用户同意`

## 命令

### 全量体检

```
bash ~/.workbuddy/skills/health-check/scripts/check.sh
```

运行 3 项巡检，输出分级结果并追加写入 `HEALTH_AUDIT.md`。

### 单项巡检

```
bash ~/.workbuddy/skills/health-check/scripts/check.sh --only tasks     # 仅巡检项1 任务假成功
bash ~/.workbuddy/skills/health-check/scripts/check.sh --only contract  # 仅巡检项2 契约完整性
bash ~/.workbuddy/skills/health-check/scripts/check.sh --only skills    # 仅巡检项3 版本一致性
bash ~/.workbuddy/skills/health-check/scripts/check.sh --only cross     # 仅巡检项4 跨模块合规性
bash ~/.workbuddy/skills/health-check/scripts/check.sh --only log       # 仅巡检项5 日志大小
bash ~/.workbuddy/skills/health-check/scripts/check.sh --only fmt       # 仅巡检项6 TASKS格式
```

### 错误判断识别（判定用户对某级别问题的选择是否违规）

```
bash ~/.workbuddy/skills/health-check/scripts/check.sh --respond P0 "暂不处理"   # → 输出第一次警告话术
bash ~/.workbuddy/skills/health-check/scripts/check.sh --respond P1 "稍后修复"   # → 提示 24h 时限并追问确认
bash ~/.workbuddy/skills/health-check/scripts/check.sh --respond P2 "忽略"       # → 放行（默认）
```

一次性判定单次选择合法/违规并输出对应话术，同时写审计。**多轮升级（首次→二次→兜底）为 AI 对话行为**，见上文「错误判断拦截规则」；脚本不追踪轮次状态。

## 错误处理与降级

1. **文件缺失**：若 `HEALTH_AUDIT.md` 不存在，自动创建，不报错。
2. **Git 未初始化**：跳过 commit 检查（巡检项 1），报 `WARNING_GIT_DISABLED`。
3. **扫描失败**：返回 `ERROR_SCAN_FAILED`，对人类说"体检工具异常，请检查版本"。

## 铁律对齐

1. **只诊断不修理**：本 Skill 不改任何业务/治理文件，修复一律经 task-manager 新开任务。
2. **不猜测结果**：脚本判定什么等级就是什么，AI 无升降级裁量权。
3. **文件为唯一真相**：所有隐患结论指向可核验的磁盘文件（TASKS-*.md / CONTRACT.md / CROSS_IMPACT_LOG.md / SKILL_REGISTRY.md）。
4. **POSIX 兼容**：`check.sh` 与 task-manager 一致，禁用 GNU AWK 三参数 match / PCRE lookbehind。
5. **状态用语统一**：本 Skill 产出文档统一用 `✅ 已完成`，不使用「✅ coordinator确认」。
6. **Registry 格式铁律**：`SKILL_REGISTRY.md` 的表格列必须严格为 `| Skill名称 | 版本 | 日期 | 描述 | 状态 |`，不得在第 2–5 列中包含 `|` 字符，以免干扰 Shell 解析。
7. **架构边界铁律**：`check.sh` 是纯工具（无状态单次扫描 / `--respond` 单次判定），多轮对话拦截（警告→兜底）属 Coordinator AI 职责，**严禁在 Shell 脚本里实现对话管理**；冻结机制严禁调用 `task-manager` 任何冻结命令、严禁脑补 `handle_freeze`，**真正的流转阻断留 TODO**。
