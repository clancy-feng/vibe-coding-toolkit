# 健康巡检（health-check）详解

> 本文是 `vibe-coding-toolkit` 中 `health-check` 子模块的用户指南。想看总览请回 [README.md](../README.md)。

## 一、模块作用

你可以把它理解成你项目的"定期体检医生"。

你用 AI 做项目，时间久了可能会悄悄积累一些问题：比如某个任务 AI 说"做完了"但其实没真提交代码、某个跨模块约定没人跟进、提交前缀写错了等等。`health-check` 就是定期，或你喊一声，给项目做个全面检查，把这些问题按严重程度列出来告诉你。

**关键特性：它只诊断、不开药。** 也就是说，它发现问题时不会自己动手改你的项目文件，只会报告并给你选项，等你授权后才通过任务系统去修。这样避免 AI 自作主张改东西。

## 二、什么时候用

- 你定期想看看项目"健不健康"。
- 项目要交付前，想做一次合规检查。
- 你怀疑某个 AI 提交可能有假、或某个约定没落实。

## 三、触发方式

| 你说的话                        | 发生什么      |
| --------------------------- | --------- |
| "给项目做个体检" / "项目体检" / "健康巡检" | 立即跑一次完整体检 |

## 四、它查什么

体检分六个项目，每一项发现的问题会被标记为三个等级之一：

- **P0 致命级**：框架本身出问题，比如治理契约文件丢了，必须立即处理。
- **P1 一般级**：合规隐患，比如 AI 声称完成但没真提交，需要你选处置方式。
- **P2 轻微级**：规范小偏差，比如工具版本号不统一，可忽略。

六项分别是：

1. **任务状态一致性**：抽查标记为"已完成"的任务，验证对应的代码提交是否真实存在，防止假成功。
2. **契约完整性**：检查治理契约文件是否存在、超时未决事项是否超 24 小时。
3. **工具版本一致性**：核对项目登记的 toolkit 版本和你实际安装的版本是否一致。
4. **跨模块改文件**：扫描近期提交，看 AI 是否改了不属于自己负责的模块文件。
5. **审计日志大小**：体检记录文件过大时提示归档。
6. **任务格式合规**：检查任务文件里的状态写法是否符合规范。

## 五、输出报告样例

跑完会输出一个分级清单，比如：

```
发现合规问题（P1）：任务 2026-08-01-PC-003 标记已完成，但 commit a1b2c3d 不存在（假成功）。
请选择：1. 立即新开修复任务  2. 稍后修复（24小时内必须处理）
```

## 六、安全说明

- 零网络、零外传。
- 会写两个文件在项目内：体检记录 `HEALTH_AUDIT.md` 和计数 `.health_state`，写之前会明确提示你。
- 只检查你项目内部的文件，不读项目以外的东西。

## 七、进阶命令

```bash
bash scripts/health-check/check.sh                  # 完整体检
bash scripts/health-check/check.sh --only tasks     # 只查第1项（任务状态）
bash scripts/health-check/check.sh --only contract  # 只查第2项（契约）
bash scripts/health-check/check.sh --only skills    # 只查第3项（版本）
bash scripts/health-check/check.sh --only cross     # 只查第4项（跨模块）
bash scripts/health-check/check.sh --only log       # 只查第5项（日志大小）
bash scripts/health-check/check.sh --only fmt       # 只查第6项（格式）
```
