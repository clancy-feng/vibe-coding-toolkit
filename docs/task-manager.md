# 任务流转（task-manager）详解

> 本文是 `vibe-coding-toolkit` 中 `task-manager` 子模块的用户指南。总览见 [README.md](../README.md)。

## 一、模块作用

它是整个治理体系的"任务调度中心"，也是这套工具的"心脏"。

> **定义**：**任务（task）** 在这里指"要 AI 做的一件具体工作"，每个任务有编号、负责人、状态，分为待处理、处理中、已完成。

所有跟"派活、记活、收活"有关的操作，都必须经过它。好处是：

- AI 不能偷偷自己干完就溜，每件事都有记录、有编号。
- 你能随时查"还有啥待办""某件事做到哪了"。
- AI 说"做完了"时，它会先调 `commit-check` 验证提交是真的，才允许标记完成。

## 二、重要：它是内部引擎，你不用手动触发

`task-manager` 没有独立的用户入口，也不会被你一句话唤醒。它是后台自动运行的：

- 当你让 AI 干活，系统自动通过它建任务、给编号。
- 当 AI 说"做完了"，它自动验证提交、记录完成。
- 当 `health-check` 发现任务异常，它自动去修正状态。

你通常不需要直接跟它打交道，但它一直在背后保证规矩落地。如果你想看任务列表，可以直接问 AI"看看还有啥待办"，AI 会调用它来回答。

## 三、工作纪律

- **所有 AI 的回复必须自带"怎么核验"的指引**：AI 不能只说"我改完了"，必须告诉你"请打开某某文件看某某内容确认"。这样你不用盲信 AI。
- **AI 说完成，人必须二次核验**：系统会自己去读任务文件和提交记录确认，而不是听 AI 嘴说。
- **权限校验**：AI 只能改自己负责的模块，越权会被拦。

## 四、和其他模块怎么联动

- 与 `commit-check`：标记任务完成前，自动先验证提交。
- 与 `health-check`：体检发现任务状态不对，通知它修正。
- 与 `project-init`：初始化完，自动建好空的任务看板。

## 五、安全说明

- 零网络、零外传。
- 它读写的是项目内的任务文件，包括 `TASKS-*.md` 等，不读项目以外的文件。
- 所有规则从你项目的治理文件动态加载，不写死在工具里。

## 六、进阶命令

```bash
bash scripts/task-manager/task-manager.sh update <task_id> <field> <value> [<actor>]
# field ∈ title / problem / change / verify / desc
# 仅对"待处理"任务生效；对已认领/完成返回 UPDATE_NOT_ALLOWED
```
