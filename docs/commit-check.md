# 提交验证（commit-check）详解

> 本文是 `vibe-coding-toolkit` 中 `commit-check` 子命令的模块指南。总览见 [README.md](../README.md)。

## 一、模块作用

当你让 AI 帮你写代码，完成后提交到 git 库，AI 干完会说"我提交好了"。但 AI 可能记错、也可能"声称提交"实际没提交、也可能提交不符合规范，`commit-check` 就是这"最后一道关"——用确定的脚本去验证 AI 的提交到底是否真实、是否合规。

> 先定义两个词：
> 
> - **commit（提交）**：Git 里的一次代码存档记录，带一个唯一编号和一段说明文字。
> - **提交前缀**：你给项目定的规矩，要求每段提交说明必须以 `[某某]` 开头，比如 `[PC]` 表示电脑端改动，方便区分是谁、改了哪块。

它验证三件事：

1. **真实性**：提交真的存在吗？工作区干净吗？
2. **合规性**：提交说明带的前缀符合你项目的规定吗？
3. **归属**：这个提交确实属于当前项目吗？防止拿别的仓库的编号来凑数。

## 二、什么时候用

- AI 每次提交后，系统会自动跑，由 `task-manager` 调用。
- 你也可以手动说"检查 commit" / "验证提交"让它跑。

## 三、触发方式

| 你说的话                          | 发生什么                                      |
| ----------------------------- | ----------------------------------------- |
| "检查 commit" / "验证提交" / "检查提交" | 全面检查：commit 真实性 + 工作区是否干净 + 前缀合规 + 归属当前项目 |

## 四、前缀规则从哪来

本工具不内置任何项目特定的前缀。允许哪些前缀，完全由你项目根目录下的 `commit-rules.yaml` 文件决定。这个文件由 `project-init` 初始化时生成，也能手动建。

文件长这样：

```yaml
prefix_check: true
prefixes:
  - PC
  - ANDROID
  - CLOUD
```

意思是：启用前缀校验，允许的前缀是 PC / ANDROID / CLOUD。

几种情况：

- 有规则且启用：校验最新一次提交的说明是否以某个允许前缀开头，否则判不合规。
- 没有规则 / 关闭校验 / 前缀为空：自动跳过前缀检查，不阻塞提交。
- 只查最新一次提交，历史提交不翻旧账。

直接编辑项目的 `commit-rules.yaml` 可修改前缀列表，参考模板见 `templates/commit-rules.example.yaml`。

## 五、输出样例

通过时：

```
[✅ 通过] commit-check

结果：
✅ commit 真实性: 通过 (a1b2c3d)
✅ commit 前缀:   通过 ([PC])
✅ commit 归属:   通过 (属于当前项目)
```

不通过会列出具体问题和修复建议，你把结果告诉 AI，改完再跑一次，直到通过为止。

## 六、安全说明

- 零网络、零外传。
- 只读你项目的 Git 历史和配置文件，不写任何文件、不读项目以外的东西。
- 不审查代码内容本身，只验证提交属性，业务逻辑对不对由你和 AI 把关。

## 七、进阶命令

```bash
bash scripts/commit-check/commit-check.sh        # 全量
bash scripts/commit-check/commit-check.sh -s     # 仅真实性（工作区+commit存在）
bash scripts/commit-check/commit-check.sh -m     # 仅前缀
bash scripts/commit-check/commit-check.sh -o     # 仅归属
```
