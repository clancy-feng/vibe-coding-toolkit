# 项目初始化（project-init）详解

> 本文是 `vibe-coding-toolkit` 中 `project-init` 子模块的用户指南。总览见 [README.md](../README.md)。

## 一、模块作用

这是这套治理工具的"奠基者"。当你准备用 AI 做开发项目，或者有个项目但很乱、没有任何治理规矩时，都可以用这个模块来搭好治理骨架。即一套固定的文件和规则，包括模块划分、角色护栏、提交前缀铁律、契约模板，让后续 AI 干活有章可循。

**关键边界**：它只生成治理文件，绝不碰你的业务代码。业务逻辑由后续的 `task-manager` + `commit-check` 管。

## 二、什么时候用

- 新项目第一次建立治理，说"初始化项目"。
- 已有项目但没治理文件，想接入这套体系，说"帮我用这套治理体系管现有项目"。
- 想改提交前缀规则、或迁移治理目录。

## 三、触发方式

| 你说的话                                                                                                      | 发生什么                  |
| --------------------------------------------------------------------------------------------------------- | --------------------- |
| "初始化项目" / "新建项目" / "新建vibe coding项目" / "新建AI开发项目" / "开个新项目" / "init vibe coding project" / "init project" | 新建治理骨架                |
| "帮我用这套治理体系管现有项目" / "给现有项目接入治理"                                                                            | 适配模式（接入已有项目）          |
| "更新提交前缀" / "修改 commit 前缀规则"                                                                               | 改前缀配置                 |
| "更新项目信息" / "修改项目配置"                                                                                       | 改项目配置（AI 回显当前值，你口述新值） |
| "迁移治理目录到xxx目录"                                                                                            | 按提供的目标路径迁移治理文件        |
| "回滚到改 X 之前" / "恢复到某个版本" / "列出历史版本"                                                                        | 本地版本管理                |

## 四、新建模式：和 AI 对话

新建项目时，你只需要做两件事：说一段话描述项目，然后确认 AI 的理解。接着 AI 会问你几个简单的选择题，每个都有大白话解释，答不上就说"你定"。

**第一步：描述你的项目**

直接说，一句话就够："我想做一个 XX，给 XX 用，大概在 XX 上用"，在哪用拿不准也没关系：

- 项目是做什么的
- 给谁用
- 大概在哪儿用

**第二步：AI 复述，你确认**

AI 会根据你的描述推断三件事，复述给你听，你说"对"或"改"：

1. **在哪里用**，可多选：电脑上装好的程序或网页；手机上用 App、网页或小程序；平板或其它设备；程序自己在后台跑，比如定时任务、服务器
2. **分几块**：AI 按使用端自动分，比如"电脑端、手机端、后台"，你也可以自己定
3. **用什么技术做**：AI 来定，你不需要懂，觉得不对可以说

**第三步：几个选择题（都有解释）**

1. 代码怎么保存：项目自带本地版本管理，用 git，完全本地不需要账号，你也不需要懂 git。确认项目目录里有没有 git 库，新项目选"还没有"
2. 给 AI 分角色：AI 按模块自动安排，一个总管加每块一个开发窗口，你确认或合并
3. 提交标签：给每块配个固定标签，比如 [PC]，提交时系统自动检查，忘了会提醒你补

**提示：**

- 所有问题答不上就说"你定"，AI 给默认方案，之后随时能改
- 生成完成后 AI 会在聊天里给你一段固定的使用引导，包含产物清单、角色方案和日常指令，照做就行

## 五、适配模式

针对"代码已有、但没治理文件"的项目：

- 先只读扫描，只看清现状，不写任何东西。
- 生成草稿放在临时目录，等你选"全量适配 / 只适配某模块 / 先看草稿"。
- 边界澄清优先：如果对话后仍搞不清项目边界，它会明确告诉你"这超出本工具设计边界，建议联系 skill 作者获取进一步帮助"，而不是硬来。

## 六、它生成哪些文件

- 在项目目录下建.vibe coding目录，其中有
- 适配层配置 `adapter.cfg`，存各路径与开关
- 系统记忆中心 `memory/`，包含 RULES.md 铁律模板、ROLES.md 角色、CONTRACT.md 契约等
- 任务看板 `TASKS-*.md`
- 提交前缀规则 `commit-rules.yaml`，这正是 `commit-check` 读取的规则来源
- 提交钩子 `.git/hooks/commit-msg`，源头拦截非法前缀

## 七、安全说明

- 零联网、零外传。
- 只生成治理配置，绝不修改你的业务代码。
- 交互中如需你的用户名 / 邮箱以便存档，会直接在聊天里问你，不会后台静默失败。

## 八、进阶（子命令）

- `update-prefixes`：改已生成的前缀规则
- `update-adapter`：改 adapter.cfg 配置 / 迁移治理目录

## 九、自带版本管理（本地 Git）

项目自带本地版本管理，用 git，完全本地运行、不需要 GitHub/Gitee 账号。初始化时自动建本地 git 库；每次任务完成，系统自动保存一个版本，提交信息为 `[模块] 任务ID: 标题`。

**用法，对 coordinator 说：**

- "任务 X 做完了" → 系统自动保存版本，不需要额外操作
- "回滚到改 X 之前" / "恢复到某个版本" → AI 先列出历史版本让你选，选好后再还原
- "列出历史版本" → 显示最近提交记录

**注意事项：**

- 版本记录在本项目目录内的 `.git/`，由系统自动管理。
- 如果从未配过本地git信息，系统自动用项目本地身份 vibe-coding-bot 提交。
