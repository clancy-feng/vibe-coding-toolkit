# 项目初始化（project-init）详解

> 本文是 `vibe-coding-toolkit` 中 `project-init` 子模块的用户指南。总览见 [README.md](../README.md)。

## 一、模块作用

它是这套治理工具的"奠基者"。当你准备用AI做开发项目，或者有个项目但很乱、没有任何治理规矩时，都可以用这个模块来搭好治理骨架。

> **定义**：**治理骨架** = 一套固定的文件和规则（模块划分、角色护栏、提交前缀铁律、契约模板），让后续 AI 干活有章可循。可以类比成"给项目立家规"。

**关键边界**：它**只生成治理文件，绝不碰你的业务代码**。业务逻辑由后续的 `task-manager` + `commit-check` 管。

## 二、什么时候用

- 新项目第一次建立治理（"初始化项目"）。
- 已有项目但没治理文件，想接入这套体系（"帮我用这套治理体系管现有项目"）。
- 想改提交前缀规则、或迁移治理目录。

## 三、怎么触发

| 你说的话                           | 发生什么                  |
| ------------------------------ | --------------------- |
| "初始化项目" / "给我的项目加治理框架" / "新项目" | 新建治理骨架                |
| "帮我用这套治理体系管现有项目"               | 适配模式（接入已有项目，只读扫描后等你选） |
| "更新提交前缀" / "修改 commit 前缀规则"    | 改前缀配置                 |
| "更新适配层配置" / "迁移治理目录"           | 改适配层配置                |

## 四、新建模式：7 轮问答（你也可以一段话带过）

工具会循序渐进地问你 7 个问题，帮它搞清楚项目长啥样：

1. 项目叫什么、干嘛的
2. 用在什么场景（电脑浏览器 / 手机 App / 后台自动跑…）
3. 模块怎么命名（比如"PC端""云端"）
4. **提交前缀规则**（⭐ 核心）：给每个模块生成前缀候选，问你是否启用前缀校验
5. **适配层配置**（⭐）：生成跨平台路径配置 + 安装提交钩子（在源头拦截非法前缀）
6. 角色分工：谁负责哪块
7. 技术栈 / 痛点 / 是否 git 初始化

> 也可以直接说一段话描述项目，它会自动解析出关键信息，回显给你确认后再生成。

## 五、适配模式（已有项目接入）

针对"代码已有、但没治理文件"的项目：

- 先**只读扫描**（只看清现状，不写任何东西）。
- 生成草稿放在临时目录，等你选"全量适配 / 只适配某模块 / 先看草稿"。
- **边界澄清优先**：如果对话后仍搞不清项目边界，它会明确告诉你"这超出本工具设计边界，建议联系 skill 作者获取进一步帮助"，而不是硬来。

## 六、它生成哪些文件（都在项目内的 `.vibe-coding/` 目录）

- 适配层配置 `adapter.cfg`（各路径与开关）
- 系统记忆中心 `memory/`（RULES.md 铁律模板、ROLES.md 角色、CONTRACT.md 契约等）
- 任务看板 `TASKS-*.md`
- 提交前缀规则 `commit-rules.yaml`（这正是 `commit-check` 读取的规则来源）
- 提交钩子 `.git/hooks/commit-msg`（源头拦非法前缀）

## 七、安全说明

- 零网络、零外传。
- 只生成治理配置，**绝不修改你的业务代码**。
- 交互中如需你的用户名 / 邮箱以便存档，会直接在聊天里问你，不会后台静默失败。

## 八、进阶（子命令）

- `update-prefixes`：改已生成的前缀规则
- `update-adapter`：改适配层配置 / 迁移治理目录
